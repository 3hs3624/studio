# SSO 전 임시 계정 접속 및 서버 기동

기준일: 2026-11-06. 현재 인증은 Django의 서버 세션/비밀번호입니다. 실제 OIDC/SAML 연동은 사용자의 요청으로 보류합니다. 인증을 생략하거나 사용자 선택으로 로그인하지 않습니다. AUTH_MODE=local만 구현하며 다른 값은 시작을 거부합니다. 기업 IdP를 흉내 내는 callback이나 가짜 성공 경로는 제공하지 않습니다.

## 함께 기동되는 구성

Caddy HTTPS → 비공개 Gunicorn/Django → PostgreSQL 16. DB·웹 포트를 직접 외부 게시하지 않고 proxy만 게시합니다. DB 초기화 소유자와 애플리케이션 역할을 분리하며, 앱 역할에는 superuser/createdb/createrole 권한을 주지 않습니다. 웹 컨테이너 시작 단계에서 migrate·정적파일 수집·최초 임시계정 발급을 완료한 뒤 Gunicorn을 기동합니다. PostgreSQL/정적파일/Caddy 인증서 볼륨을 유지하고 재기동 시 기존 계정·비밀번호를 변경하지 않습니다.

```
python deploy/configure.py
docker compose -f deploy/compose.yaml up -d --build
```

localhost 기본값은 127.0.0.1:8080/8443만 바인딩합니다. 접속은 https://localhost:8443/login/ 입니다. Caddy의 localhost 인증서는 자체 CA를 사용하므로 신뢰 설치가 필요하며, 임의 인증서 경고 무시는 운영 방안이 아닙니다. 이 주소는 서버 내부/로컬 접속용이며 사용자의 다른 PC에서 같은 서버에 접속하는 외부 주소가 아닙니다.

실제 외부 공개 서버에서는 먼저 DNS·방화벽·서버 접근권한을 확보한 후 빈 배포 디렉터리에서 `python deploy/configure.py --hostname 실제도메인`으로 생성합니다. 80/443 바인딩·Caddy 자동 공인 TLS·호스트/CSRF 허용 주소가 함께 설정됩니다. 서버/DNS/ACME 접근이 없으면 공인 주소나 인증서를 발급할 수 없습니다. 기존 .env는 덮어쓰지 않으며 임의로 다시 생성하여 DB 비밀번호를 바꾸지 않습니다.

기업 내부 CA/망분리·접근 제한·백업·모니터링·고가용성 요구는 해당 운영환경에 맞춰 추가 검증해야 합니다. 이 구성만으로 운영 출시 인수를 완료한 것으로 보지 않습니다.

## 접속 계정

최초 빈 설치에서만 `bootstrap_local_access`가 실행됩니다. temp-admin(조직관리), temp-manager(서비스처리), temp-employee(요청), temp-assets(자산/재고), temp-buyer(구매)를 만들고 각기 다른 난수 비밀번호를 발급합니다. temp-admin은 업무 승인/처리 권한을 자동으로 갖지 않습니다. demo의 공통 비밀번호 방식을 외부 접속에 사용하지 않습니다.

계정 정보는 `deploy/access/temporary-accounts.json`에 0600 권한으로 기록합니다. `.env`도 0600이며 두 경로 모두 Git에 올리지 않습니다. Docker 이미지에 계정/환경/DB/첨부 파일을 넣지 않습니다. 발급 파일을 잃어도 재기동으로 비밀번호를 초기화하지 않으며 운영자가 Django changepassword 등 명시적인 복구 절차를 수행해야 합니다. 생성 파일을 로그·공개 이슈·PR에 붙여넣지 않습니다.

계정은 조직/역할/CSRF·비활성 검사·세션 회수·감사를 그대로 적용합니다. 중지 계정은 비밀번호가 맞아도 로그인 단계에서 거부합니다. 새 설치에는 실제 업무 자료/데모 구매·계약을 넣지 않습니다. 계정 생성·권한 부여의 CLI 사용은 서버 관리 권한을 가진 운영자에게 한정합니다.

## 프록시 신뢰와 비밀정보

TRUST_PROXY_HEADERS=1은 Compose의 비공개 web 서비스 뒤에서만 사용합니다. Caddy가 전달 헤더를 설정하며 외부 사용자가 web에 직접 접근할 수 있는 배포에서는 이 설정을 그대로 신뢰해서는 안 됩니다. 모든 외부 접속은 TLS·Secure 쿠키를 사용합니다. 사용자명/비밀번호/쿠키를 URL 쿼리나 소스에 저장하지 않습니다.

관리형 빌드 환경의 프록시 CA가 필요하면, 이미지에 복사하지 않고 BuildKit의 proxy_ca secret으로 pip 단계에만 전달합니다. TLS 검증을 끄지 않습니다.

## SSO 전환 준비와 이후 작업

인증 뒤의 Person·역할·업무 인가·회수 계약은 로컬/SSO 공통으로 유지합니다. 외부 식별자는 issuer+subject(또는 검증된 SAML 식별자)로 매핑하고 이메일만으로 임의 연결하지 않도록 설계합니다. 실제 IdP 프로토콜·메타데이터·클레임·회수 정책과 테스트 계정이 확보된 뒤 어댑터를 구현합니다.

IdP 전환 후 신규 SSO 관리자/업무 계정을 검증하고 마지막 관리자 보호를 고려해 임시 계정을 순서대로 중지·세션 회수합니다. 로컬 인증 비활성화/비상계정 정책은 실제 전환 시 별도로 구현·검증하며, 현재 설정만 바꾸면 SSO가 동작한다고 표시하지 않습니다. Workflow 버전 관리 범위는 기존 명세대로 유지합니다.



# 통합 ITSM 기능명세서

기준일 2026-11-16 · main 구현 / 검증 기록 / 미완료 범위

## 1. 문서 적용 기준

이 문서는 현재 개발 소스와 검증한 화면을 기준으로 합니다. 요구사항 전체 인수 완료나 글로벌 벤더 제품과의 기능 동등성을 뜻하지 않습니다. 구현·연결 준비·후속 확장을 구분합니다. 배포 커밋과 검증 기록은 마지막 절에 기록합니다. 사용자·고객 데이터, 비밀번호, 인증 키는 포함하지 않습니다.

## 2. 제품 범위와 역할

IT서비스: 서비스요청·장애·구성 관리·SLA/SLM. IT자산: 자산 생애주기·구매·입고·지급·재고. IT자원: GitHub 형상 및 Jenkins 빌드·배포 관리와 변경 소스/배포 현황. 현재 IT자원은 수신 스냅샷 기반 조회가 중심이며 실제 GitHub/Jenkins 운영 연동은 별도 검증이 필요합니다.

사용자: 포털을 이용해 신청·조회·할당 업무·결재를 수행합니다. 운영자: 콘솔에서 플랫폼 기능으로 업무를 구성·설정·게시하고 시스템을 관리합니다. 개발자: 바이브 코딩으로 플랫폼 패치·기능 개선·테스트·배포를 수행합니다. 시스템 관리자는 보안·계정·권한을 관리하며 업무별 관리자 역할은 별도로 부여합니다.

## 3. 기능 목록과 상세 규칙

### COMMON-01 · 통합 포털·업무 영역

로그인 조직의 업무·역할·메뉴에 따라 IT서비스·IT자산·IT자원 이동과 현황을 표시합니다. 집계와 상세에 같은 데이터 경계를 적용합니다. 운영 콘솔 버튼은 허용 역할만 표시하고 새 탭으로 엽니다.

메뉴·API: /

데이터·근거: Person, RoleMenuPolicy, navigation.py

검증·예외: 자기 이름 선택 시 본인 정보 모달. 권한 변경 시 기존 세션 재확인.

### IAM-01 · 사용자 관리

검색은 한 줄, 생성 필드는 행당 3개입니다. 개인정보는 UserProfile 별도 테이블로 관리하고 계정 인증정보와 구분합니다. 부서는 부서 목록에서 선택하고 직접/상속 역할과 그룹의 출처를 확인합니다.

메뉴·API: /console/users

데이터·근거: Person, UserProfile, CredentialState

검증·예외: 조회·수정·발급 권한과 재인증 필요. 비밀번호는 다시 조회하지 않습니다.

### IAM-02 · 할당 복제

신규 생성에서 기존 사용자 또는 부서의 역할·그룹을 미리 보고 선택 복제합니다. 서명된 임시 토큰에 조직·원본·선택 범위를 고정하고 생성 시 재검증합니다. 직접 복사는 원본의 후속 변경을 따라가지 않습니다.

메뉴·API: /console/users

데이터·근거: RoleGrant, CustomRoleGrant, Membership

검증·예외: 부서 상속은 동적으로 유지. 개인정보·비밀번호·세션·MFA는 복제하지 않음.

### IAM-03 · 부서 트리

탐색기 형태의 계층 탐색, 생성·편집·활성/비활성, 상위 부서 지정. 부서별 역할·그룹과 상위 상속의 출처를 표시합니다.

메뉴·API: /console/access?tab=departments

데이터·근거: Department, ScopedRoleGrant, GroupDepartment

검증·예외: 순환·다른 조직 참조·보호 관리자 우회 배정을 차단. 낙관적 버전 충돌 검사.

### IAM-04 · 역할·그룹 배정

역할 선택 시 사용자·부서·그룹 3영역에 배정합니다. 그룹 선택 시 사용자·부서 2영역에 소속을 설정합니다. 하위 부서 포함은 명시 선택합니다. 직접 권한과 상속 권한을 합산하되 업무 데이터 범위는 기존 업무 권한과 함께 검사합니다.

메뉴·API: /console/access?tab=roles

데이터·근거: RoleDefinition, Group, ScopedRoleGrant, GroupDepartment

검증·예외: 기본 역할·보호 관리자 제약을 유지. 배정 변경 근거와 전후 이력 기록.

### IAM-05 · 역할↔메뉴·콘솔·데이터 범위

역할에 메뉴와 운영 콘솔 버튼을 매핑합니다. 화면의 숨김뿐 아니라 URL·API 호출을 통제합니다. 지원 업무의 조회/입력 범위를 자기·할당·부서·하위부서·기존 범위로 구분합니다.

메뉴·API: /console/access?tab=menus

데이터·근거: RoleMenuPolicy, RoleDataPolicy

검증·예외: 업무 권한이 없는 계정에 메뉴 표시만으로 업무 데이터를 무조건 허용하지 않습니다. 관리 복구 경로 유지.

### SEC-01 · 보안 정책·사용자 상태

정책 목록→상세에서 비밀번호 길이·복잡도·변경 주기·재사용·로그인 실패 제한·잠금·세션 유효시간·동시 세션·재인증·MFA/관리 접근 제한 등을 설정합니다. 계정 중지·만료·세션 회수·보안 이력을 연계합니다.

메뉴·API: /console/security

데이터·근거: SecurityPolicyVersion, SecurityEvent, LoginSession, CredentialState

검증·예외: 적용 전 검증·영향 확인과 감사 근거. 정책만으로 모든 보안취약점 진단 통과를 보장하지 않습니다.

### DATA-01 · 엔티티 목록·필드 그리드

목록에서 엔티티를 생성하고 상세에서 필드를 그리드로 구성합니다. 논리 유형 21개와 길이·정밀도·소수 자릿수·기본값·설명을 지원합니다. 유형·필수·선택값·참조를 검증한 뒤 스키마 버전을 게시합니다. 물리 DB 타입 매핑·복합 업무 PK·UI 인덱스 DDL은 미구현입니다.

메뉴·API: /console/entities

데이터·근거: EntityDefinition, EntitySchemaVersion

검증·예외: 게시된 스키마는 불변. 기존 레코드는 생성 때의 스키마 버전을 참조.

### DATA-02 · 시스템 필드·관계

id, 조직, 스키마 버전, 생성/수정 시각·생성/수정자, row_version 등 시스템 필드는 서버가 관리합니다. 단일·복수 참조와 일대일 유일성, 역관계 조회, 중간 엔티티의 좌우 참조를 지원합니다.

메뉴·API: /console/entities

데이터·근거: EntityRecord, EntityRecordLink

검증·예외: 일대다의 기준 FK 방향을 명확히 합니다. 조직·조회범위·대상 스키마·카디널리티를 검증합니다.

### FORM-01 · 공통 화면 정의·버전

공통 화면의 필드와 그룹·열 수·조회 전용 기본값을 정의하고 게시합니다. 화면 디자이너에서 클릭/드래그 추가·이동·크기 조정·우클릭 속성을 편집하고 동일 항목표에 반영합니다. 워크플로우 공통 또는 태스크별 게시 화면 버전을 연결합니다.

메뉴·API: /console/screens

데이터·근거: ProcessDefinition(SCREEN), ProcessVersion

검증·예외: 최대 30필드·20그룹·1~3열. 그룹 나열/탭, 빠른 속성·검색·복제·실행 취소, 데스크톱/모바일 미리보기를 지원합니다. 미리보기 입력은 저장하지 않으며 태스크 권한 시뮬레이션은 아닙니다. 상세 절차는 7절을 따릅니다.

### WF-01 · 워크플로우 설계·검토·게시

초안 저장→검증→다른 검토자의 독립 검토→게시. 노드·연결·조건·참조·자동 순환·병렬 합류·확장 깊이를 검사합니다. 이전 게시 버전으로 새 초안을 복제하고 신규 실행을 퇴역시킬 수 있습니다.

메뉴·API: /console/workflows

데이터·근거: ProcessDefinition, ProcessReview, ProcessVersion, ProcessRetirement

검증·예외: 실행은 게시 그래프를 고정합니다. 실행 중 프로세스의 자동 버전 이관은 지원하지 않습니다.

### WF-02 · 조건·병렬·시간 대기

조건별 경로, 병렬 분기·모든 경로 합류, 시간 대기, 선언된 필드의 안전한 데이터 갱신을 지원합니다. 임의 실행 코드·eval은 사용하지 않습니다.

메뉴·API: /console/workflows

데이터·근거: ProcessRun, ProcessTask, ProcessArrival

검증·예외: 시간 대기는 run_platform_worker 실행 필요. 무료 웹 휴면 중 정시 처리는 보장하지 못합니다.

### WF-03 · 복수 담당·결재선

사용자·역할·그룹·부서 기준 담당자를 정하고 1명 또는 여러 명의 ANY/ALL 처리를 지원합니다. 태스크 처리 전/후에 게시 결재선을 연결하거나 독립 결재 노드를 둡니다.

메뉴·API: /console/approval-lines

데이터·근거: ProcessTask, ProcessAssignment, ProcessVote

검증·예외: 담당자 목록은 태스크 생성 때 고정하고 실행 시 현재 자격도 재검증. 자기 신청의 결재는 배제. 미할당 차단·재배정 이력 유지.

### WF-04 · 상하위 프로세스·이관

변경 프로세스에서 여러 하위 작업지시를 별도 실행으로 생성하고 모두 완료되면 상위를 재개합니다. 어떤 프로세스에서도 타 프로세스로 이관하며 원본·대상 연결과 최종 완료 흐름을 보존합니다.

메뉴·API: /console/workflows

데이터·근거: ProcessRun.parent_task/root_run, ProcessTask.child_ids

검증·예외: 하위 반려·실패·취소·출력 충돌은 상위를 차단. 보완 재실행·출력 조정은 사유와 이력을 남깁니다.

### WF-05 · 태스크별 화면 필드·데이터 권한

동일 화면에 태스크별 그룹 및 필드의 숨김·조회·입력과 조회/입력 역할을 설정합니다. 필드별 필수도 설정합니다. 그룹 제한을 필드 설정으로 해제할 수 없습니다. 업무 목록·상세의 행 데이터 범위는 별도 적용합니다.

메뉴·API: /processes

데이터·근거: ProcessVersion.graph, RoleDataPolicy

검증·예외: 서버가 숨김 값을 반환하지 않고 읽기전용·허용되지 않은 입력을 거부합니다. 화면 숨김을 보안 경계로만 사용하지 않습니다.

### WF-06 · API 노드

게시된 API 버전을 선택하고 프로세스 변수↔API 입력/결과를 매핑합니다. 영속 큐 호출의 성공 후에만 다음 노드로 진행합니다.

메뉴·API: /console/workflows

데이터·근거: IntegrationJob.process_task, ProcessTask(API)

검증·예외: 허용 워크플로우를 API에도 지정해야 합니다. 실패는 차단 상태로 보존. 재처리로 완료된 노드를 중복 진행하지 않습니다.

### ITSM-01 · 서비스 카탈로그·요청

서비스 항목·신청 필드·대상 그룹·공개 범위를 게시하고 사용자가 서비스요청을 생성합니다. 요청자는 진행·댓글·증적을 조회하고 담당자는 처리합니다.

메뉴·API: /catalog, /work/catalog

데이터·근거: CatalogItem, CatalogVersion, ServiceRequest, Ticket

검증·예외: 새 카탈로그에 게시 워크플로우를 연결할 수 있습니다. 연결 시 기존 단일 승인 흐름과 새 엔진이 이중 처리하지 않습니다.

### ITSM-02 · 장애·구성항목 연결

장애 접수·배정·처리·보류·해결·종료·재개 및 댓글·자원 연결을 제공합니다. 구성항목은 IT서비스 영역에서 관리합니다.

메뉴·API: /portal/incidents, /work/incidents, /cis

데이터·근거: Ticket, ConfigurationItem, TicketResource, StatusHistory

검증·예외: 담당 그룹·담당자·요청자 권한과 상태 전이를 검사합니다. 완전한 CMDB 관계/영향 분석은 후속입니다.

### SLM-01 · SLA·업무 달력

업무 시간·요일·휴일·시간대를 설정하고 응답·해결 목표와 경고/보류 정책을 버전 관리합니다. 요청별 정책을 고정하고 시계 이벤트·알림을 추적합니다.

메뉴·API: /console/sla

데이터·근거: BusinessCalendar, SLAPolicy, SLAInstance, SLAClockEvent

검증·예외: 정책 변경이 과거 요청 목표를 무단 덮어쓰지 않습니다.

### SLM-02 · 적기처리율·확정 보고서

기본은 접수시각 기준이며 고객 합의에 따라 기준일·협의일·완료기한·목표시간·업무 달력을 변경 가능한 정책으로 게시합니다. 완료시각/기한을 비교해 자동 산출·CSV 추출합니다.

메뉴·API: /console/slm

데이터·근거: TimelinessPolicy, TimelinessTarget, TimelinessReport, TimelinessEvent

검증·예외: 기한 내 완료/산정 대상×100. 완료 기간과 기한도래 기간을 구분. 취소/반려 제외, 초과 미완료·기한 미설정·시각 불명은 별도 표시.

### ITAM-01 · 자산 생애주기

자산 등록·조회·변경·검수·지급·반납·이동·폐기 및 지급 이력을 관리합니다.

메뉴·API: /assets, /my-assets

데이터·근거: Asset, AssetCustody, AssetHistory

검증·예외: 조직·자산번호·일련번호·상태·보유자 범위와 변경 버전을 검증합니다.

### ITAM-02 · 구매·계약·입고·재고

구매요청·승인·발주·부분 입고·창고·재고 이동·출고를 연결하며 수량·중복 입고·재고 음수를 통제합니다.

메뉴·API: /procurement, /inventory, /contracts

데이터·근거: PurchaseRequisition, PurchaseOrder, GoodsReceipt, StockBalance, StockMovement

검증·예외: 승인·수량·재시도 중복·동시성 검증. 계약/입고/이동 근거는 보존합니다.

### ITRM-01 · GitHub·Jenkins 현황

### API-01 · API 목록·상세·버전

목록→상세에서 REST/JSON·SOAP/XML·고정 GraphQL·Webhook 입력 계약·실행 계정·호스트·인증·매핑·시간 제한·재시도를 구성하고 게시 버전을 선택 호출합니다.

### API-03 · 인증·외부 호출 계정

Bearer/Basic/API Key/OAuth2 client credentials를 암호화 보관합니다. 수신/호출 계정에는 버전별 API Key/HMAC 서명·분당 제한·중지·중복 호출 키를 적용합니다.

## 4. 공통 운영 계약·설계 제한

### 사용자·운영자·개발자

사용자는 업무 포털과 할당된 업무·결재를 처리합니다. 운영자는 운영 콘솔의 엔티티·화면·워크플로우·결재선·API·코드·플러그인을 구성하고 게시합니다. 개발자는 바이브 코딩으로 플랫폼 코드를 수정하고 테스트·패치·배포합니다. 개발→검증→독립 검토→게시→실행 버전 고정→증적 보존을 기본 절차로 합니다.

### 조직·권한

`/console/access`의 역할·그룹·메뉴·부서·이력 탭에서 관리합니다. 역할은 사용자·부서·그룹에, 그룹은 사용자·부서에 배정합니다. 부서 하위 포함은 명시적으로 선택하며 직접 복사한 할당은 독립된 배정입니다. 메뉴와 운영 콘솔 버튼을 역할에 매핑하고 URL/API에서도 검사합니다. 데이터 범위는 기존 업무 권한과 교집합으로 작동합니다. 시스템 관리자 역할은 개인정보·권한관리자이지 모든 업무 데이터의 자동 관리자라는 뜻은 아닙니다. 업무별 관리자 권한은 별도로 배정하십시오.

신규 사용자는 사용자 또는 부서의 역할·그룹을 미리 보고 복제할 수 있습니다. 부서 상속과 직접 복제의 출처를 구분합니다. 비밀번호·개인정보는 복제하지 않습니다. 사용자 정보 모달은 상단 본인 이름으로 엽니다.

### 화면·워크플로우·데이터

`/console/screens`, `/console/workflows`, `/console/approval-lines`에서 초안 구성 후 작성자와 다른 사람의 검토를 받아 게시합니다. 게시 버전과 실행 그래프를 보존합니다. 공통 화면을 워크플로우에 연결하고 태스크별 HIDDEN/READ/EDIT·필수·조회/입력 역할을 설정합니다. 서버가 숨김·읽기전용 입력을 차단합니다.

지원 노드: 시작, 업무, 결재, 조건, 병렬 분기·합류, 시간 대기, 하위 프로세스 다중 호출, 타 프로세스 이관, 선언된 데이터 갱신, 게시 API 호출, 종료. 업무는 1명/복수 인원 ANY/ALL 처리합니다. 하위 실행을 모두 완료해야 상위가 진행하며 실패·반려·출력 충돌은 차단 후 근거를 남겨 보완합니다. 이관은 특정 업무에 한정되지 않습니다.

서비스요청의 메뉴 연결은 새 카탈로그 게시에 기본 적용합니다. 기존 카탈로그와 진행 건은 유지합니다. 연결된 요청은 새 엔진만 상태·결재를 관리합니다. 다른 업무의 자동 연결에는 업무 어댑터가 추가로 필요합니다.

### SLM · 적기처리율

`/console/slm`: 기본 접수시각+24시간, 정책 버전으로 고객 합의 기준과 목표 분·업무 달력을 설정합니다. 요청별 기준을 고정하고 실제 완료 시각으로 산출합니다. 재개하면 최종 완료 시각을 다시 추적합니다. 완료 기간·기한 도래 기간을 구분하며 미완료 초과건·미설정·시각 불명·취소/반려 제외를 별도 표시합니다. 보고서 확정과 CSV는 조회 범위와 산출 근거를 보존합니다. 기존 정책의 소급 덮어쓰기는 하지 않습니다.

### API · 데이터 연계

`/console/integrations` 목록에서 생성 후 상세에서 구성·게시·호출합니다. REST/JSON, SOAP/XML, 고정 GraphQL, Webhook 수신을 지원합니다. OpenAPI 3.x/Swagger2 JSON의 작업·기본 입력을 가져오며 본문·참조·인증·매핑은 운영자가 검토합니다. 전체 OpenAPI 호환이나 WSDL 자동 생성은 제공하지 않습니다.

인증 NONE/Bearer/Basic/API Key/OAuth2 client credentials. 인증정보는 암호화하여 별도 보관하고 조회 결과·감사·명령 재실행 응답에 비밀 값을 노출하지 않습니다. SECRET_KEY는 암호화 키 파생에 사용하므로 백업하고 임의 교체하지 마십시오. 별도 KMS 키 회전은 후속 확장입니다.

보안 관리자의 HTTPS 호스트 허용, DNS/IP 검증·연결 IP 고정, TLS 검증, 리다이렉트 거부, XML DTD/외부 엔티티 거부, 응답 크기 제한을 적용합니다. 서버 실행 계정·조직·호출 허용 역할/워크플로우를 검사합니다. 업무 상태를 바꾸는 API는 WRITE로 분류하십시오.

원본 경로→목표 항목 매핑, 자료형·문자변환·코드변환·기본값·필수 검증. 엔티티 적재는 게시 스키마와 원본 식별자 기준으로 중복을 판별하고 중복 건너뛰기 또는 개정 추가를 지원합니다. 개정 추가는 기존 불변 레코드를 변경하지 않고 새 레코드+연계 개정 이력을 남기므로 엔티티 일반 목록에는 과거 개정도 보일 수 있습니다. 최신 전용 데이터셋 UI는 후속입니다.

호출은 영속 큐로 처리합니다. 읽기 또는 대상 멱등성이 보장된 호출만 자동 재시도합니다. 결과가 불확실한 변경 호출은 UNKNOWN으로 남겨 자동 재호출하지 않습니다. 응답 매핑 실패는 보관 응답을 다른 게시 매핑 버전으로 재처리할 수 있습니다. 외부 호출 자체를 되풀이하지 않습니다.

외부 계정 발급은 버전별 API Key/HMAC-SHA256, 중지·분당 제한·호출 키 중복 방지를 지원합니다. 비밀 값은 발급 때 1회 표시됩니다.

`POST /api/integration-clients/{client_id}/call` 입력=등록한 입력 JSON.

`GET /api/integration-clients/{client_id}/jobs/{job_id}` 결과 조회.

API Key: `Authorization: Bearer <secret>`, 두 경로 모두 `Idempotency-Key` 동일 값 필요.

HMAC: `X-Integration-Timestamp` UNIX 초(±300초), `X-Integration-Signature` hex HMAC-SHA256. 서명 문자열은 `METHOD + '\n' + PATH + '\n' + TIMESTAMP + '\n' + IDEMPOTENCY_KEY + '\n' + raw_body` UTF-8 바이트입니다. GET 본문은 빈 바이트입니다. 표준 자체 계약이며 개별 제품의 Webhook 서명 형식은 별도 어댑터가 필요합니다.

### 실행·배포

`python manage.py run_platform_worker`가 API 큐와 워크플로우 시간 대기를 실행합니다. `--once`는 단발 실행입니다. 로컬 AP Compose에 worker를 추가하고 기존 DB·자격증명·Neon 연결은 바꾸지 않았습니다. Render는 초기화 후 웹+워커 감독 프로세스를 실행합니다. 자식 실패 시 함께 종료해 플랫폼 재시작을 받으며 SIGTERM을 전달합니다.

Render 무료 웹 서비스가 휴면 중이면 워커도 실행되지 않습니다. 재가동 후 기한 지난 대기를 처리하지만 정확한 시각 보장은 불가합니다. 상시 SLA 운영에는 상시 실행 AP/전용 워커가 필요합니다. 실제 외부 API·GitHub/Jenkins·SSO의 현장 연결은 연결정보와 별도 통합 검증이 필요하며 완료로 간주하지 않습니다.

### COMMON-02 · 목록 → 생성 → 상세

화면·워크플로우·결재선 관리는 별도 목록에서 이름/코드 검색·사용 상태 필터·25개 단위 페이지를 제공합니다. 코드·이름·사용 여부로 새 정의를 생성한 뒤 해당 상세로 이동합니다. 상세의 설계·초안 / 버전·검토·게시 / 업무 연결 / 실행 현황 탭을 사용하며 목록으로 돌아가 다른 정의를 선택합니다. 미저장 이동 경고를 제공합니다. 생성만으로 게시되지는 않으며 결재선은 단계를 추가해야 합니다.

### FORM-02 · 디자이너 편집·저장·미리보기

화면 관리 목록 → 정의 상세 → 설계·초안 → 화면 디자이너 열기. 왼쪽에서 그룹을 선택하고 유형 아이콘을 클릭하거나 대상 그룹의 빈 영역/제목/탭에 끌어 필드를 추가합니다. 필드를 끌어 순서·그룹을 변경하고 오른쪽 아래 핸들로 너비·높이를 조절합니다. 우클릭/더블클릭/Shift+F10으로 상세 속성을 편집합니다. Ctrl+방향키는 이동, Shift+방향키는 크기 조정입니다. 오른쪽 그룹/필드 영역에서 빠른 속성을 바꾸고 검색·복제·실행 취소/다시 실행을 사용할 수 있습니다.

그룹은 나열 또는 탭으로 전환합니다. 최대 20그룹·30필드, 화면 1~3열, 너비는 화면 열 수 이내, 높이는 48px 단위 1~5입니다. 화면 미리보기는 현재 편집 배치·필수·조회 전용·설명·리터럴 기본값을 데스크톱/모바일 형태로 보여 줍니다. 입력값은 저장하지 않습니다. 자동 기본값·사용자 목록·태스크별 권한은 실제 업무에서 적용됩니다.

저장 사유 → 디자이너의 초안 저장으로 실제 저장·검증합니다. 적용하고 닫기는 항목표에만 반영하므로 바깥 화면에서 초안 저장·검증이 필요합니다. 취소·닫기는 미적용 편집을 버립니다. 이후 작성자와 다른 검토자가 독립 검토하고 게시해야 신규 실행에 적용됩니다. 오류 안내와 버튼이 늘어나던 UI를 수정했으며 검토자 분리 규칙은 유지합니다.

### FORM-03 · 그룹·필드 통제 우선순위

게시 화면을 워크플로우 공통 화면 또는 태스크별 화면에 연결합니다. 그룹 숨김 → 그룹 조회 역할 → 그룹 모드/입력 역할 → 필드 모드/역할 → 화면 조회 전용 → 태스크 할당 순으로 제한을 합성합니다. 그룹 입력 허용은 필드 제한을 따르게 하는 뜻입니다. 결재/완료 태스크는 조회 전용이며 빈 그룹은 탭에서도 제외합니다. 서버가 숨김 값을 응답에서 제외하고 허용되지 않은 변경을 거부합니다. 그룹/필드 통제와 목록의 행 범위 권한은 별개입니다.

### WF-07 · 선택 단계 중심 편집

단계 목록 또는 흐름도에서 하나를 선택해 유형에 필요한 속성만 편집합니다. 다음/반려/조건/합류 경로를 단계 이름으로 선택합니다. 식별자 변경은 직접 참조·분기·시작점·배치 좌표를 함께 갱신하고 삭제 후 남은 참조는 게시 전 검증합니다. 그룹·필드 권한은 고급 설정에서 펼칩니다. 게시 버전과 진행 중 실행은 유지하며 새 게시본으로 자동 이관하지 않습니다.

### COMMON-03 · 내가 할 일: 전체 / 부서 / 나

통합 홈과 IT서비스 현황에서 todo_scope를 선택하며 기본값은 나입니다. 전체는 기존 메뉴·업무·행 조회 권한 안의 대기 업무, 부서는 담당자의 현재 소속 부서 기준(하위 부서 제외), 나는 본인 할당 업무입니다. 부서가 없으면 0건과 안내를 표시합니다. 범위 선택으로 권한이 확대되지는 않습니다.

열린 워크플로우 업무/결재, 워크플로우 미연결 서비스요청 승인·배정, 배정된 진행 중 장애를 집계합니다. 완료·취소·비활성 할당·본인의 자기 결재와 이미 본인이 처리한 전원 처리 태스크를 제외합니다. 연결된 서비스요청은 워크플로우 태스크로만 집계하며 복수 담당 태스크도 1건입니다. 총건수와 최근 생성 10건을 보여 주고 상세에서도 기존 권한을 검사합니다. 내 승인·알림의 개인 집계와는 구분합니다.

### DATA-03 · 논리 타입·기본값과 미구현 경계

엔티티 21개 논리 유형 중 화면 팔레트는 선택/공통코드/엔티티 참조를 제외한 18개입니다. 문자 길이 1~65535(지원 문자 유형), DECIMAL precision 1~38·scale 0~min(precision,18)을 검증합니다. DECIMAL은 문자열로 보존하고 JSON 크기/깊이·유한 수치, 시간대 포함 일시, UUID/email/phone/HTTP URL 등을 검증합니다. 기본값은 리터럴 또는 허용된 CURRENT_TIMESTAMP/CURRENT_DATE/UUID만 사용하고 신규 생성 시에만 적용합니다.

화면 배치와 그룹/필드 권한은 ProcessVersion.graph JSON에, 동적 엔티티 필드는 EntitySchemaVersion.fields와 EntityRecord.data에 저장합니다. 물리 스키마 변경 기능을 뜻하지 않습니다. 게시본/기존 실행은 보존됩니다. 현재 변경 영향도는 게시 화면/엔티티 참조 및 진행 건 중심으로 한정되며 모든 API·규칙 의존성을 추적하지는 않습니다.

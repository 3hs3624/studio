# ADR-001: 첫 구현 기술 스택

상태: 첫 구현에 적용. 결정일: 2026-11-04.

## 결정

Python 3.12 + Django 5.2 LTS, 서버 렌더링 HTML·CSS·소규모 JavaScript, Django ORM·마이그레이션을 사용합니다. PostgreSQL 16을 운영 DB 기준으로 삼고 SQLite는 로컬 개발·빠른 테스트에 한정합니다. 의존성은 requirements.txt에 버전을 고정했습니다.

## 이유와 대안

인증·세션·CSRF·ORM·스키마 이관·테스트가 있는 Django로 업무 규칙을 먼저 검증합니다. React+별도 API 서버는 복잡한 대화형 화면에 유리하지만 첫 수직 업무 흐름에는 빌드·계약·배포 경계를 추가합니다. Spring Boot도 기업 운영에 적합하나 현재 Python 개발 환경과 첫 구현 속도를 기준으로 Django를 선택했습니다. 디자인 시스템·워크플로 편집기가 복잡해지면 별도 클라이언트를 평가합니다.

[Django 5.2 릴리스 문서](https://docs.djangoproject.com/en/5.2/releases/5.2/)에서 LTS 지정과 Python 지원을 참고했습니다. 프레임워크 지원이 자체 보안·운영 검증을 대신하지 않습니다.

## 정합성·동시성

첫 버전의 명령은 조직 행→사용자 행→티켓 행 순서로 잠급니다. PostgreSQL에서 조직 단위 직렬화와 row_version 검증으로 동시 명령을 제어합니다. 이 방식은 조직별 쓰기 처리량을 제한합니다. 고도화 시 대상별 잠금·관리 명령의 잠금 순서·교착 테스트를 함께 설계해야 합니다.

SQLite의 select_for_update는 PostgreSQL과 같지 않습니다. 쓰기 경합은 409로 반환할 수 있으며 운영 동시성 보증에 사용하지 않습니다. PostgreSQL 전용 실제 연결 동시성 테스트를 별도로 둡니다.

## 인증·배포 결정

첫 버전은 Django 로컬 비밀번호 인증·서버 세션이며 고정 로그인이나 계정 선택 우회 기능은 없습니다. SSO/OIDC/SAML·MFA·인사 연동은 아직 구현하지 않았습니다. 하나의 사용자는 하나의 조직에 속합니다. 다중 고객사 SaaS 인증·조직 전환 모델로 간주하지 않습니다.

DEBUG 기본값은 false이며 운영 모드는 비밀키와 PostgreSQL 설정 없이는 시작하지 않습니다. HTTPS·Secure 쿠키·CSRF·보안 헤더를 적용합니다. 초기 로그인 시도 제한은 프로세스 로컬 캐시입니다. 다중 워커 운영 전 공유 속도 제한·인증 모니터링을 구성해야 합니다.

외부 알림 어댑터는 미구현입니다. outbox 워커는 로컬 이벤트 sink와 재시도 상태만 제공합니다. 실제 메일·메신저 전송과 전달 보장은 후속 기능입니다.

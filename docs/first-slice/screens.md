# 첫 구현 화면·권한 명세 — v0.1

대상: ITSM-02/05, PLT-01/02/06/07, AST-01·CFG-01의 **조회·티켓 연결 부분**. 완료 시 해당 기능 ID 전체 완료로 표시하지 않습니다. 첫 묶음에는 SLA 계산·승인·파일 업로드·자산 수정·카탈로그·자유 워크플로 편집이 없습니다.

## 역할별 권한

| 동작 | 직원 | 담당자 | 서비스 관리자 | 조직 관리자 |
|---|---|---|---|---|
| 장애 생성·본인 공개 조회 | 허용 | 허용 | 허용 | 직원 권한 |
| 다른 직원 장애 조회 | 금지 | 소속 담당 그룹만 | 해당 조직 전체 | 자동 부여 없음 |
| 그룹·담당자 배정 | 금지 | 현재 그룹 내 배정만 | 조직 내 그룹 간 배정 | 자동 부여 없음 |
| 내부 댓글·내부 이력 | 금지 | 허용 범위 | 허용 범위 | 자동 부여 없음 |
| 처리·대기·해결 | 금지 | 본인 담당 건 | 허용 범위 | 자동 부여 없음 |
| 해결 확인·재개방 | 본인 건 | 요청자일 때 또는 관리자 역할 | 허용 범위 | 요청자일 때 |
| 자산·CI 조회·연결 | 공개 허용 자산·CI만 | 조회 권한 별도 필요 | 조회 권한 별도 필요 | 자동 부여 없음 |
| 조직·그룹·역할 관리 | 금지 | 금지 | 금지 | 해당 조직만 |

모든 역할은 활성 조직에 한정합니다. 관리자 권한도 다른 조직으로 확장되지 않습니다. 담당자 조직 권한과 그룹 소속 변경은 기존 세션의 다음 요청부터 반영합니다. 직원 조회 정책은 requested_by=self로 고정하고 대리 신청은 후속 범위로 둡니다.

## 상태 전이

| 현재 | 다음 | 권한·조건 |
|---|---|---|
| NEW | ASSIGNED | triage 관리자, 유효 그룹·담당자 지정 |
| ASSIGNED | IN_PROGRESS | 본인 담당자 또는 서비스 관리자 |
| IN_PROGRESS | PENDING | 담당자 또는 관리자, 대기 사유 필수 |
| PENDING | IN_PROGRESS | 담당자 또는 관리자 |
| IN_PROGRESS | RESOLVED | 담당자 또는 관리자, 해결 내용 필수 |
| RESOLVED | CLOSED | 요청자 또는 관리자, 확인 내용 기록 |
| RESOLVED | IN_PROGRESS | 요청자 또는 관리자, 재개방 사유 필수, 기존 배정 유지 |

첫 버전에서 CLOSED는 최종 상태입니다. 자동 종료·취소·삭제·SLA 시계는 후속 범위입니다. 우선순위는 영향도×긴급도 표로 계산하며 사용자 직접 입력을 받지 않습니다: (1,1)=P1; (1,2)/(2,1)=P2; (1,3)/(2,2)/(3,1)=P3; (2,3)/(3,2)=P4; (3,3)=P5. 숫자 1은 높은 영향/긴급도입니다.

## 접근성·안전한 화면 동작

키보드 이동·명확한 필드 라벨·오류 연결·상태 텍스트를 제공합니다. 내부 댓글은 표시와 확인을 명확히 하고 생성 후 공개 전환은 첫 버전에 허용하지 않습니다. 403/404에서 대상 제목·사용자 정보가 노출되지 않아야 합니다. 감사 전체 JSON을 직원 활동 목록으로 그대로 제공하지 않습니다.

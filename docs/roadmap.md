# 개발 로드맵 — v0.2

## 계획 원칙

전체 범위를 기능 대응표로 관리하고 업무 흐름 단위로 출시합니다. 아래 단계는 순서이며 계약 일정이 아닙니다. 기존 8~12명·12~18개월 추정은 검증되지 않은 가정으로, 범위·인력·연동 확인 후 다시 산정합니다.

| 단계 | 산출물·범위 | 선행 조건 | 통과 기준 |
|---|---|---|---|
| 0. 범위·근거 확정 | IBM 대응 근거, 대상 고객·운영 방식, 우선순위, ADR | 현재 문서 검토 | 필수 기능·연동·제외 범위·성능·복구 목표 명시 |
| 1. 공통 플랫폼 | PLT-01~07, 인증, 스키마·설정·감사·워커 | 0단계 결정 | 조직 간 접근 차단, 버전 고정 승인, 중복 이벤트 안전성 검증 |
| 2. 서비스 운영 | ITSM-01~10, AST-01/02, CFG-01/02 | 권한·워크플로·이력 | 포털→장애 처리→SLA→종료, 자산·CI 연결 시범 운영 |
| 3. 자산 수명주기 | PRC·INV·CTR·FIN | 자산·승인·재고 규칙 | 신청→구매→부분 입고→지급→반납·폐기 시나리오 |
| 4. 통제·구성 | ITSM-11, CHG·REL, CFG-03/04 | 티켓·CI·설정 버전 | 문제→변경→실패·복구→검토와 대사 충돌 처리 |
| 5. 고급 관리 | SAM·INT·RPT | 계약·수집·규칙 기반 | 사용권 계산 근거, 증분 연동·복구, 권한 적용 보고 |

## 첫 구현 묶음

우선 인증·조직·역할, 최소 Ticket·Incident·StatusHistory, 담당 그룹, 공개·내부 댓글, 감사, 최소 Asset·CI 연결을 만듭니다. 이 묶음의 인수 기준은 직원 접수→허용된 그룹 배정→담당자 해결→직원 확인·종료이며, 권한 위반·재개방·동시 수정도 확인합니다. 전체 제품 완성으로 표시하지 않습니다.

화면·권한, API 계약, DB 명세와 인수 계획은 [첫 구현 명세](first-slice/screens.md)에 초안을 작성했습니다. 기술 스택 ADR과 실행 마이그레이션·코드는 아직 없습니다. 메뉴 초안은 직원 포털 / 내 업무 / 서비스 데스크 / 변경·릴리스 / 자산 / 구성 / 구매·재고 / 계약·라이선스 / 지식 / 보고서 / 관리입니다. 아직 구현하지 않은 메뉴는 운영 화면에서 완료 기능처럼 노출하지 않습니다.

## 단계별 공통 완료 조건

- 기능 ID별 정상·예외·권한·동시성 검증과 증거가 있습니다.
- 데이터 마이그레이션·복원·감사·연동 실패 복구를 확인합니다.
- 운영 안내·설정 변경 절차와 알려진 제한을 문서화합니다.
- 성능은 합의된 데이터량·동시성에서 측정합니다.
- 필수 업무의 미해결 결함이 있으면 다음 운영 출시를 막습니다.

## 주요 위험과 대응

| 위험 | 대응 |
|---|---|
| IBM 대응 범위가 불명확 | 대상 버전·모듈을 확정하고 행별 공식 근거 기록 |
| 공통 엔진 과대 개발 | 실제 업무 2개 이상에서 필요한 설정부터 일반화 |
| CMDB 데이터 품질 | 식별·출처·중복·대사·담당자 정책을 수집 전에 정의 |
| 라이선스 계산 복잡성 | 측정 규칙별 지원 범위와 미지원 상태 표시 |

| 연동·이관 지연 | 초기 샘플·샌드박스·오류 계약으로 검증 |

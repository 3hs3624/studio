# 통합 IT 운영 포털

세 시스템을 하나의 로그인과 조직 경계 안에서 전환합니다. 기존 데이터를 이행하거나 DB 스키마를 변경하지 않습니다.

| 영역 | 진입 | 현재 업무 메뉴 |
|---|---|---|
| 통합 포털 | / | 시스템 선택, 자주 찾는 업무, 내 승인·알림 |
| IT서비스 | /systems/service | 서비스 카탈로그·내 요청·내 장애·승인함, 장애/요청 처리, 카탈로그·SLA/달력 설정 |
| IT자산 | /systems/asset | 자산 대장·내 지급 자산, 구매 요청/승인·발주/입고·계약, 창고/재고·이동 이력 |
| IT자원 | /systems/resource | 구성항목 현황·대장·상세 |
| 공통 | /notifications, /admin/access | 알림, 조직·권한 관리 |

메뉴는 기존 역할로 표시하며 ORG_ADMIN을 다른 업무 관리자로 간주하거나 권한을 자동 부여하지 않습니다. 숨겨진 메뉴의 직접 URL/API 접근도 기존 서버 권한 검사를 그대로 따릅니다. 서비스 현황은 담당자는 조회 가능한 처리 큐, 일반 사용자는 본인 요청을 집계합니다. 자산·CI의 공개/소유/역할 조회 범위를 대시보드와 최근 목록에도 적용하고 타 조직 항목을 집계하지 않습니다.

상단은 세 시스템의 전환 메뉴, 좌측은 선택한 시스템의 전용 업무 메뉴, 하단은 공통 업무입니다. 기존 상세 URL로 직접 접속해도 올바른 시스템과 메뉴를 표시합니다. 기본 로그인은 통합 홈으로 이동하되 인증의 안전한 next 경로를 유지합니다. 모바일은 가로 스크롤 없는 카드와 업무 메뉴를 사용합니다.

이는 화면·정보 구조 및 기존 기능 통합 단계입니다. 범용 Workflow 버전 관리, Problem/Change/Release, IT자원 자동 수집·관계/영향 분석·용량/성능 등은 이 변경에 포함하지 않습니다. 새 메뉴에 미구현 기능을 동작하는 것처럼 노출하지 않습니다. 실제 SSO는 계속 보류합니다.

검증: 조직·역할·공개/비공개 자산/CI 집계와 최근 목록 분리, 세 시스템 메뉴 분리, 중첩 URL 선택 표시, 로그인 기본 진입/기존 URL을 테스트합니다. 로컬 Chromium에서 비밀번호 로그인과 세 시스템 전환, 390/768/1024px 가로 넘침 및 JavaScript 오류를 검사했습니다. Render 배포 시 기존 다섯 역할의 로그인과 네 가지 진입 화면도 확인합니다.

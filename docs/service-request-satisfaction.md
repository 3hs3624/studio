# 서비스요청 만족도 프로세스 초기 구성

> 운영 적용 상태: 코드와 로컬 검증은 완료했으며 신규 계정·템플릿·실습 요청 5건의 운영 DB 초기 적재는 비밀번호 전달 승인 대기입니다. 기존 운영 계정과 진행 요청은 유지됩니다.

기준일: 2026-11-18. 기존 SR_STANDARD/화면/결재선/카탈로그에 새 게시 버전을 추가합니다. 기존 게시 버전과 진행 건은 유지하고 이전 초안은 *_B20261118 정의로 보관합니다. 초기 템플릿은 사용자 요청에 따른 시스템 자동 구성·검증이며 사람이 수행한 독립 검토를 주장하지 않습니다. 이후 수정은 디자이너 초안 → 다른 검토자 검토 → 게시 절차를 사용합니다.

## 역할·계정

| 로그인 ID | 역할 | 주요 업무 |
|---|---|---|
| user1 | 요청자 | 신청, 결과 확인, 만족도 제출 |
| user_auth1 | 요청부서 승인자 | 같은 요청부서의 승인·반려 |
| worker1 | 운영자1 | 접수·배정 및 본인 할당 조치 |
| worker2 | 운영자2 | 접수·배정 및 본인 할당 조치 |
| developer1 | 개발자 | 구성 검토·게시, 플랫폼 기능 설정 |
| designer1 | 서비스요청 디자이너 | 화면·워크플로우·카탈로그 구성; 독립 검토 권한 없음 |

기존 로그인 계정·비밀번호는 재사용합니다. 없는 계정만 생성하고 초기 비밀번호는 별도 접속정보로 전달합니다. 새 계정은 첫 로그인에서 비밀번호를 변경합니다. 디자이너의 service.manage 권한은 카탈로그 구성을 위해 필요하며 서비스 운영 데이터 조회 범위를 포함하므로 일반 요청자에게 배정하지 않습니다. 사용자 개인정보는 기존 UserProfile 분리 저장 정책을 유지합니다.

## 실행 절차

요청 등록 → 요청부서 승인 → 접수 및 담당자 배정(접수그룹 ANY) → 배정된 운영자 조치(FIELD_USER) → 요청자 확인 → 만족도 조사(1~5점) → 자동 종료.

확인이 ‘아니오’이면 조치로 돌아갑니다. 만족도 점수가 낮아도 유효한 조사 제출이면 종료합니다. 조치 완료·정상 확인만으로 종료되지 않습니다. 승인 반려는 반려 종료하며 새 카탈로그 양식으로 재신청합니다.

## 화면·태스크 매핑

공통 화면은 요청 기본정보/접수 및 배정/담당자 조치/조치결과 확인/만족도 조사 5개 그룹, 업무 필드 19개입니다. 신청 카탈로그는 같은 게시 화면의 그룹·너비/높이를 초기 7개 입력 항목에 적용합니다. 처리용 필드는 신청 때 노출하지 않습니다. 런타임 서버는 숨김 값을 제외하고 조회 전용·비할당 입력을 거부합니다.

| 단계 | 입력 가능한 그룹 | 필수 | 담당 |
|---|---|---|---|
| 등록 | 요청 기본정보 | 제목·내용·구분·시스템·우선순위 | user1 |
| 승인 | 없음(조회 + 승인/반려·사유) | 결정 | user_auth1 |
| 접수/배정 | 접수 및 배정 | assignee·receipt_note | SR_DEMO_INTAKE: worker1/2 |
| 조치 | 담당자 조치 | resolution | assignee에 선택된 한 사람 |
| 확인 | 조치결과 확인 | confirmed | 시작 요청자 |
| 만족도 | 만족도 조사 | satisfaction(정수1~5) | 시작 요청자 |

그룹 READ/HIDDEN 제한은 필드 허용보다 우선합니다. 요청정보·다른 단계 데이터는 조회 또는 숨김이며 기존 완료 태스크는 조회 전용입니다. 버튼은 할당·상태·권한이 충족되는 열린 태스크에만 제공됩니다.

## 초기 적재·샘플

요청/운영 부서, 접수 전용 그룹(worker1/2), 신청 대상 그룹, 디자이너 역할, 요청 구분 공통코드, 화면·결재선·워크플로우·메뉴 바인딩·카탈로그를 구성합니다. 기존 서비스요청 KPI 정책이 없을 때만 접수시각 기준 1,440분 정책을 추가합니다. 고객 협의 기준은 SLM 정책/합의 기한 관리에서 변경합니다.

[실습] 업무 시스템 계정 생성 / 공유폴더 접근 권한 / 개발 도구 설치 / 업무 노트북 점검 / 업무 시스템 사용 문의, 5건을 user1 명의로 등록합니다. 배포 환경에서는 모두 승인 대기로 준비하며 자동 검증용 요청은 롤백해 남기지 않습니다. 로컬 브라우저 검증에서는 이 중 한 건을 종료까지 진행했습니다.

## 실행·보존

```
python manage.py migrate --noinput
python manage.py setup_service_request_demo --organization-id <조직 UUID> --password-file <비밀 JSON 파일>
```

비밀 JSON은 없는 계정의 로그인 ID를 키로, 서로 다른 초기 비밀번호를 값으로 지정합니다. 공개 소스나 매뉴얼에 비밀번호를 기록하지 않습니다. 재실행은 SR_DEMO_20261118 마커로 기존 결과를 반환하며 비밀번호·버전·샘플을 중복 생성하지 않습니다. --no-samples는 기준정보만 준비합니다.

Render에서는 명시적 STUDIO_SR_DEMO_ENABLED=1, STUDIO_SR_PROVISION_ORGANIZATION_ID, STUDIO_SR_DEMO_PASSWORDS_JSON 설정으로 시작 시 실행합니다. 기존 환경변수는 교체하지 않고 해당 키만 병합합니다. 기본값은 미실행입니다. 설치형/노트북 Docker는 최신 이미지와 동일 명령을 각 DB에 적용해야 합니다.

## 검증

전체 엔진의 승인·배정·조치·재조치·확인·만족도·종료 및 KPI 완료시각을 실제 서비스 명령 경로에서 롤백 검증합니다. 비할당 운영자의 조치/요청자의 만족도 외 필드 위조, 점수 범위, 기존 계정/초안/진행 버전 보존 및 중복 실행을 테스트합니다. 로컬 브라우저에서 역할 6개의 로그인·최초 비밀번호 변경·구성 화면 접근과 등록부터 자동 종료까지 확인했습니다. 새 DB 마이그레이션은 없습니다.

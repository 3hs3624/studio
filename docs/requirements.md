# 요구사항 — v0.1

## 목표와 범위

범위의 기준은 [기능 대응표](maximo-feature-matrix.md)입니다. IBM 화면 복제보다 업무 결과와 설정 가능 범위를 기준으로 인수합니다. 아직 구현된 기능은 없습니다.

## 사용자와 접근

| 역할 | 주요 권한 | 제약 |
|---|---|---|
| 직원 | 허용된 카탈로그 신청·본인 요청 확인 | 다른 직원의 요청 열람 금지 |
| 승인자 | 배정된 승인 의사결정 | 자기 승인 기본 금지; 예외는 정책과 감사 필요 |
| 서비스 담당자 | 허용된 그룹 티켓 처리 | 조직·그룹 범위 적용 |
| 자산·구성 관리자 | 자산·CI와 관계 관리 | 재고 조정·폐기는 승인 정책 적용 |
| 변경 관리자 | 변경 심사·일정·결과 관리 | 실행자와 승인자 분리 가능 |
| 구매·계약·라이선스 담당자 | 해당 도메인 업무 | 금액·계약 정보 별도 권한 |
| 플랫폼 관리자 | 양식·규칙·권한 설정 | 모든 업무 데이터 접근을 자동 부여하지 않음 |
| 감사 담당자 | 허용된 기록 조회·추출 | 업무 원본 수정 금지 |

## 대표 인수 시나리오

### S-01 장비 신청부터 반납까지

ITSM-04/05 → PLT-04 → PRC-01/02 또는 INV-01 → AST-01/02 → CTR-01.

1. 직원이 카탈로그 양식으로 신청하고 부서장이 승인합니다.
2. 재고가 있으면 예약·출고하고, 없으면 구매 요청과 주문을 생성합니다.
3. 분할 입고를 기록하며 식별 가능한 장비를 자산으로 등록합니다.
4. 지급 확정 시 사용자·위치·상태·재고 이동을 일관되게 반영합니다.
5. 반납·재지급·폐기 시 이력과 원 요청을 추적합니다.

예외: 반려·취소·미입고·검수 불합격·동시 출고·처리 중 퇴사. 재고 부족 시 지급 완료를 허용하지 않습니다.

### S-02 장애에서 문제·변경까지

ITSM-02/06/11 → CFG-02/04 → CHG-01/02/03 → ITSM-08.

1. 장애 접수 시 영향도·긴급도로 우선순위를 계산하고 서비스·CI를 연결합니다.
2. 담당 그룹과 SLA 정책 버전을 고정하고 처리 시간을 계산합니다.
3. 반복 장애는 문제와 연결하고 원인·우회책을 기록합니다.
4. 해결을 위한 변경에 영향·위험·실행·복구 계획을 작성하고 승인받습니다.
5. 실행 결과를 확인하고 실패 시 복구, 성공 시 장애 해결과 지식 게시를 진행합니다.

예외: 중복 경보·긴급 변경·승인 거부·일정 충돌·변경 실패·장애 재개방. 문제 종료가 관련 장애를 자동 종료하지 않습니다.

### S-03 소프트웨어 사용권 대사

INT-01 → SAM-01/02/03 → CTR-01.

수집 데이터 정규화 → 계약과 측정 규칙 선택 → 설치·사용권 대사 → 초과·미사용 검토 → 회수·구매 결정. 계산에 사용한 원본·규칙 버전·기준일을 보존합니다. 알 수 없는 제품이나 지원하지 않는 규칙은 적합 판정하지 않습니다.

## 상태와 시간 규칙

- 요청: 접수→승인 대기→처리 중→완료→종료. 반려·취소·재신청은 명시적 경로로 정의합니다.
- 장애: 접수→배정→처리 중→대기→해결→종료. 재개방 사유와 SLA 재개 정책이 필요합니다.
- 변경: 초안→평가→승인→예약→실행→검토→종료. 실패·복구·취소 경로를 별도 둡니다.
- 게시된 워크플로·양식·SLA는 버전으로 보존합니다. 진행 중 건에 대한 새 버전 적용은 명시적 이관 절차를 거칩니다.
- 시각은 UTC로 저장하고 사용자 시간대로 표시합니다. SLA는 지정된 업무 달력·휴일·시간대·대기 사유로 계산합니다.
- 우선순위 매트릭스, 대기 중 SLA 정지 여부, 재개방 누적 방식은 설정값으로 명시합니다.

## 운영·보안 인수 조건

- UI·API·검색·첨부 다운로드·내보내기에 동일한 권한 정책을 적용합니다.
- 비밀정보는 환경별 비밀 저장소로 관리하고 로그에 남기지 않습니다. 입력·첨부 크기 제한 및 악성 파일 처리 정책이 필요합니다.
- 감사는 주체·행위·대상·시각·이유·변경 내용을 남깁니다. 민감 필드 마스킹과 보존 기간은 정책으로 확정합니다.
- 동시 수정은 버전 충돌을 반환합니다. 연동·재시도는 중복 업무를 생성하지 않아야 합니다.
- 백업 복원 리허설, 마이그레이션 검증, 관측 지표와 오류 추적을 출시 조건에 포함합니다.
- 접근성은 WCAG 2.2 AA를 목표로 키보드·포커스·양식 오류 안내를 검증합니다.
- 사용자 수·자산 수·동시 요청·p95 응답시간·가용성·RPO/RTO는 미확정입니다. 수치 합의와 부하 모델 없이 운영 준비 완료로 판정하지 않습니다.

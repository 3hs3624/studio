# 업무 구성 프레임워크 · 2026-11-14

## 사용자·운영자·개발자
사용자는 업무 포털과 할당된 업무·결재를 처리합니다. 운영자는 운영 콘솔의 엔티티·화면·워크플로우·결재선·API·코드·플러그인을 구성하고 게시합니다. 개발자는 바이브 코딩으로 플랫폼 코드를 수정하고 테스트·패치·배포합니다. 개발→검증→독립 검토→게시→실행 버전 고정→증적 보존을 기본 절차로 합니다.

## 조직·권한
`/console/access`의 역할·그룹·메뉴·부서·이력 탭에서 관리합니다. 역할은 사용자·부서·그룹에, 그룹은 사용자·부서에 배정합니다. 부서 하위 포함은 명시적으로 선택하며 직접 복사한 할당은 독립된 배정입니다. 메뉴와 운영 콘솔 버튼을 역할에 매핑하고 URL/API에서도 검사합니다. 데이터 범위는 기존 업무 권한과 교집합으로 작동합니다. 시스템 관리자 역할은 개인정보·권한관리자이지 모든 업무 데이터의 자동 관리자라는 뜻은 아닙니다. 업무별 관리자 권한은 별도로 배정하십시오.

신규 사용자는 사용자 또는 부서의 역할·그룹을 미리 보고 복제할 수 있습니다. 부서 상속과 직접 복제의 출처를 구분합니다. 비밀번호·개인정보는 복제하지 않습니다. 사용자 정보 모달은 상단 본인 이름으로 엽니다.

## 화면·워크플로우·데이터
`/console/screens`, `/console/workflows`, `/console/approval-lines`에서 초안 구성 후 작성자와 다른 사람의 검토를 받아 게시합니다. 게시 버전과 실행 그래프를 보존합니다. 공통 화면을 워크플로우에 연결하고 태스크별 HIDDEN/READ/EDIT·필수·조회/입력 역할을 설정합니다. 서버가 숨김·읽기전용 입력을 차단합니다.

지원 노드: 시작, 업무, 결재, 조건, 병렬 분기·합류, 시간 대기, 하위 프로세스 다중 호출, 타 프로세스 이관, 선언된 데이터 갱신, 게시 API 호출, 종료. 업무는 1명/복수 인원 ANY/ALL 처리합니다. 하위 실행을 모두 완료해야 상위가 진행하며 실패·반려·출력 충돌은 차단 후 근거를 남겨 보완합니다. 이관은 특정 업무에 한정되지 않습니다.

서비스요청의 메뉴 연결은 새 카탈로그 게시에 기본 적용합니다. 기존 카탈로그와 진행 건은 유지합니다. 연결된 요청은 새 엔진만 상태·결재를 관리합니다. 다른 업무의 자동 연결에는 업무 어댑터가 추가로 필요합니다.

## SLM · 적기처리율
`/console/slm`: 기본 접수시각+24시간, 정책 버전으로 고객 합의 기준과 목표 분·업무 달력을 설정합니다. 요청별 기준을 고정하고 실제 완료 시각으로 산출합니다. 재개하면 최종 완료 시각을 다시 추적합니다. 완료 기간·기한 도래 기간을 구분하며 미완료 초과건·미설정·시각 불명·취소/반려 제외를 별도 표시합니다. 보고서 확정과 CSV는 조회 범위와 산출 근거를 보존합니다. 기존 정책의 소급 덮어쓰기는 하지 않습니다.

## API · 데이터 연계
`/console/integrations` 목록에서 생성 후 상세에서 구성·게시·호출합니다. REST/JSON, SOAP/XML, 고정 GraphQL, Webhook 수신을 지원합니다. OpenAPI 3.x/Swagger2 JSON의 작업·기본 입력을 가져오며 본문·참조·인증·매핑은 운영자가 검토합니다. 전체 OpenAPI 호환이나 WSDL 자동 생성은 제공하지 않습니다.

인증 NONE/Bearer/Basic/API Key/OAuth2 client credentials. 인증정보는 암호화하여 별도 보관하고 조회 결과·감사·명령 재실행 응답에 비밀 값을 노출하지 않습니다. SECRET_KEY는 암호화 키 파생에 사용하므로 백업하고 임의 교체하지 마십시오. 별도 KMS 키 회전은 후속 확장입니다.

보안 관리자의 HTTPS 호스트 허용, DNS/IP 검증·연결 IP 고정, TLS 검증, 리다이렉트 거부, XML DTD/외부 엔티티 거부, 응답 크기 제한을 적용합니다. 서버 실행 계정·조직·호출 허용 역할/워크플로우를 검사합니다. 업무 상태를 바꾸는 API는 WRITE로 분류하십시오.

원본 경로→목표 항목 매핑, 자료형·문자변환·코드변환·기본값·필수 검증. 엔티티 적재는 게시 스키마와 원본 식별자 기준으로 중복을 판별하고 중복 건너뛰기 또는 개정 추가를 지원합니다. 개정 추가는 기존 불변 레코드를 변경하지 않고 새 레코드+연계 개정 이력을 남기므로 엔티티 일반 목록에는 과거 개정도 보일 수 있습니다. 최신 전용 데이터셋 UI는 후속입니다.

호출은 영속 큐로 처리합니다. 읽기 또는 대상 멱등성이 보장된 호출만 자동 재시도합니다. 결과가 불확실한 변경 호출은 UNKNOWN으로 남겨 자동 재호출하지 않습니다. 응답 매핑 실패는 보관 응답을 다른 게시 매핑 버전으로 재처리할 수 있습니다. 외부 호출 자체를 되풀이하지 않습니다.

외부 계정 발급은 버전별 API Key/HMAC-SHA256, 중지·분당 제한·호출 키 중복 방지를 지원합니다. 비밀 값은 발급 때 1회 표시됩니다.
`POST /api/integration-clients/{client_id}/call` 입력=등록한 입력 JSON.
`GET /api/integration-clients/{client_id}/jobs/{job_id}` 결과 조회.
API Key: `Authorization: Bearer <secret>`, 두 경로 모두 `Idempotency-Key` 동일 값 필요.
HMAC: `X-Integration-Timestamp` UNIX 초(±300초), `X-Integration-Signature` hex HMAC-SHA256. 서명 문자열은 `METHOD + '\n' + PATH + '\n' + TIMESTAMP + '\n' + IDEMPOTENCY_KEY + '\n' + raw_body` UTF-8 바이트입니다. GET 본문은 빈 바이트입니다. 표준 자체 계약이며 개별 제품의 Webhook 서명 형식은 별도 어댑터가 필요합니다.

## 실행·배포
`python manage.py run_platform_worker`가 API 큐와 워크플로우 시간 대기를 실행합니다. `--once`는 단발 실행입니다. 로컬 AP Compose에 worker를 추가하고 기존 DB·자격증명·Neon 연결은 바꾸지 않았습니다. Render는 초기화 후 웹+워커 감독 프로세스를 실행합니다. 자식 실패 시 함께 종료해 플랫폼 재시작을 받으며 SIGTERM을 전달합니다.

Render 무료 웹 서비스가 휴면 중이면 워커도 실행되지 않습니다. 재가동 후 기한 지난 대기를 처리하지만 정확한 시각 보장은 불가합니다. 상시 SLA 운영에는 상시 실행 AP/전용 워커가 필요합니다. 실제 외부 API·GitHub/Jenkins·SSO의 현장 연결은 연결정보와 별도 통합 검증이 필요하며 완료로 간주하지 않습니다.

## 검증과 후속 범위
SQLite 회귀 278개 통과(15개 PostgreSQL 전용 건은 CI 검증 대상), 로컬 Docker 제어 단위테스트 3개, 브라우저 API 생성·게시·호출 및 화면 크기 1280/768 검증. 후속 집중 테스트 23개에서 API·태스크 타이머·카탈로그 연결도 통과했습니다. 전체 최종 테스트 목록은 280개입니다.

후속: 전체 ITIL 업무 어댑터, BPMN 전체 규격, 시각적 폼 배치 디자이너, 이벤트 기반 대기·위임·에스컬레이션, 워크플로우 외 화면 이벤트에서 API를 선택 실행하는 바인딩 UI, WSDL·OpenAPI 고급 스키마, SFTP/JDBC/대용량 파일 ETL, 분산 워커 부하·복원·장시간 운영 검증. 글로벌 제품과 기능 동등성을 의미하지 않습니다.

# 무료 DB 장기 사용: Neon 이전 준비

기준일: 2026-11-06. 현재 Render 무료 PostgreSQL의 기간 연장은 지원되지 않으므로, Render 웹을 유지하고 Neon 무료 PostgreSQL로 이전하는 안을 준비합니다. Neon의 무기한 무료 보장은 하지 않으며 현행 용량/사용량·유휴 중지 조건을 적용합니다. 유료 전환은 포함하지 않습니다.

## 현재 상태

현재 서비스는 Render에서 Live입니다. 원본 DB 만료 예정은 2026-12-06 14:36(KST)입니다. 이번 준비 단계에서 DATABASE_URL·Blueprint·DB 접근 허용 목록·비밀번호·데이터를 바꾸지 않습니다. Neon 계정은 아직 연결되지 않았으므로 프로젝트/대상 DB 생성 및 데이터 이전은 미수행입니다.

Django 접속 주소 해석에 Neon의 표준 sslmode=require&channel_binding=require를 지원했습니다. TLS 비활성화·채널 바인딩 비활성화·중복/알 수 없는 옵션은 거부하고 URL/비밀번호를 로그에 출력하지 않습니다. 이 변경은 호환성 준비이며 실제 Neon 연결 성공의 증거가 아닙니다.

## 계정 연결 후 실행할 절차

1. Neon 계정/조직·Free 플랜·이용 한도를 확인하고 전용 프로젝트와 DB를 준비합니다. 기존 프로젝트의 데이터나 결제 플랜은 변경하지 않습니다.
2. 원본과 대상 DB의 PostgreSQL 버전·확장·트리거/함수·권한 호환성을 확인하고 소규모 샘플 복원으로 검증합니다. 트랜잭션 풀러 제약이 있으면 이관에는 직접 연결을 사용합니다.
3. 데이터 규모·스키마·원본 접근 경로·백업 보존 위치와 쓰기 중지 시간을 확정합니다. 무료 Render 웹은 SSH/일회성 작업 제약이 있어 실제 사용할 백업/복원 실행 경로를 확인한 뒤 진행합니다. 검증을 위해 DB를 전체 인터넷에 열지 않습니다.
4. 일관된 백업/복원으로 사용자·비밀번호 해시·역할·세션·업무·감사·이력·시퀀스·보호 트리거를 보존합니다. 파일에 비밀값/해시가 포함될 수 있으므로 공개 저장소나 채팅에 넣지 않습니다. 원본 연결 정보는 비밀 저장소에서 취급합니다.
5. 데이터 복사와 전환 사이의 쓰기 손실을 방지하도록 쓰기 중지/대사/전환 창을 두고 동시 쓰기가 없는지 확인합니다. 원본과 대상 모두 쓰는 이중 운영은 하지 않습니다.
6. 테이블별 건수·키/참조·핵심 값·시퀀스·트리거/불변성·조직 경계를 대사하고, 대상에서 로그인·권한·기존 업무 처리와 재기동을 검증합니다. 계정을 새로 발급해 기존 사용자/데이터를 덮어쓰지 않습니다.
7. Render DATABASE_URL을 대상 비밀 연결로 전환합니다. Blueprint의 fromDatabase가 원본 DB 주소를 다시 덮어쓰지 않도록 선언도 함께 정리하고 변경 계획을 검토/승인한 뒤 재배포합니다. SECRET_KEY와 계정 비밀번호는 변경하지 않습니다.
8. Render Live와 공개 URL·정적파일·인증/CSRF·업무 쓰기/읽기·재기동 보존을 확인합니다. 실패하면 쓰기를 정지하고 원본으로 복구하되 전환 이후 발생한 쓰기의 대사/복구까지 처리합니다.
9. 검증 완료 후에만 원본 보존 종료를 별도로 결정합니다. 기존 Render DB 삭제나 유료 과금은 자동으로 수행하지 않습니다.

## 완료 기준과 남은 전제

완료 기준은 Neon 대상 확인 + 데이터/권한 대사 + 새 DB로 웹 Live + 로그인/업무/재기동 검증 + 복구 절차 확인입니다. 접속 문자열 파싱 시험만으로 DB 이전 완료라고 하지 않습니다.

현재 필요한 사용자 조치는 Neon 추가 및 계정 연결입니다. 비밀번호/접속 URL을 일반 채팅에 붙여넣을 필요는 없습니다. 연결 후에도 실제 원본 백업 접근과 쓰기 중지 경로가 확보되지 않으면 원본 서비스를 그대로 유지하고 해당 제약을 알립니다.

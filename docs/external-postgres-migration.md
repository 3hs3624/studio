# 무료 DB 장기 사용: Neon 이전 준비

기준일: 2026-11-06. 현재 Render 무료 PostgreSQL의 기간 연장은 지원되지 않으므로, Render 웹을 유지하고 Neon 무료 PostgreSQL로 이전하는 안을 준비합니다. Neon의 무기한 무료 보장은 하지 않으며 현행 용량/사용량·유휴 중지 조건을 적용합니다. 유료 전환은 포함하지 않습니다.

## 현재 상태

현재 서비스는 Render에서 Live입니다. 원본 DB 만료 예정은 2026-12-06 14:36(KST)입니다. 사용자 요청으로 Neon Free 계정 연결을 확인하고 Singapore/PostgreSQL 16 전용 프로젝트를 준비했습니다. 전환 완료 여부는 실제 배포 로그와 Neon 대조 결과로 확인하며, 원본 DB 삭제와 유료 플랜 변경은 포함하지 않습니다.

Django 접속 주소 해석에 Neon의 표준 sslmode=require&channel_binding=require를 지원했습니다. TLS 비활성화·채널 바인딩 비활성화·중복/알 수 없는 옵션은 거부하고 URL/비밀번호를 로그에 출력하지 않습니다. 이 변경은 호환성 준비이며 실제 Neon 연결 성공의 증거가 아닙니다.

## 계정 연결 후 실행할 절차

1. Neon 계정/조직·Free 플랜·이용 한도를 확인하고 전용 프로젝트와 DB를 준비합니다. 기존 프로젝트의 데이터나 결제 플랜은 변경하지 않습니다.
2. 원본과 대상 DB의 PostgreSQL 버전·확장·트리거/함수·권한 호환성을 확인하고 소규모 샘플 복원으로 검증합니다. 트랜잭션 풀러 제약이 있으면 이관에는 직접 연결을 사용합니다.
3. 데이터 규모·스키마·원본 접근 경로·백업 보존 위치와 쓰기 중지 시간을 확정합니다. 무료 Render 웹은 SSH/일회성 작업 제약이 있어 실제 사용할 백업/복원 실행 경로를 확인한 뒤 진행합니다. 검증을 위해 DB를 전체 인터넷에 열지 않습니다.
4. 일관된 백업/복원으로 사용자·비밀번호 해시·역할·세션·업무·감사·이력·시퀀스·보호 트리거를 보존합니다. 파일에 비밀값/해시가 포함될 수 있으므로 공개 저장소나 채팅에 넣지 않습니다. 원본 연결 정보는 비밀 저장소에서 취급합니다.
5. 데이터 복사와 전환 사이의 쓰기 손실을 방지하도록 쓰기 중지/대사/전환 창을 두고 동시 쓰기가 없는지 확인합니다. 원본과 대상 모두 쓰는 이중 운영은 하지 않습니다.
6. 테이블별 건수·키/참조·핵심 값·시퀀스·트리거/불변성·조직 경계를 대사하고, 대상에서 로그인·권한·기존 업무 처리와 재기동을 검증합니다. 계정을 새로 발급해 기존 사용자/데이터를 덮어쓰지 않습니다.
7. Render DATABASE_URL을 대상 비밀 연결로 전환합니다. Blueprint의 fromDatabase가 원본 DB 주소를 다시 덮어쓰지 않도록 선언도 함께 정리하고 변경 계획을 검토/승인한 뒤 재배포합니다. SECRET_KEY와 계정 비밀번호는 변경하지 않습니다.
8. Render Live와 공개 URL·정적파일·인증/CSRF·업무 쓰기/읽기·재기동 보존을 확인합니다. 실패하면 쓰기를 정지하고 원본으로 복구하되 전환 이후 발생한 쓰기의 대사/복구까지 처리합니다.
9. 검증 완료 후에만 원본 보존 종료를 별도로 결정합니다. 기존 Render DB 삭제나 유료 과금은 자동으로 수행하지 않습니다.

## 완료 기준과 남은 전제

완료 기준은 Neon 대상 확인 + 데이터/권한 대사 + 새 DB로 웹 Live + 로그인/업무/재기동 검증 + 복구 절차 확인입니다. 접속 문자열 파싱 시험만으로 DB 이전 완료라고 하지 않습니다.

Neon 계정은 연결되었습니다. 비밀번호/접속 URL을 일반 채팅에 붙여넣을 필요는 없습니다. 실제 이전과 서비스 전환은 아래 도구의 검증 결과로 판정합니다.

## 실행 도구와 복구

`NEON_MIGRATION_TARGET_URL`은 이전 중에만 주입하는 직접 연결 비밀값입니다. `/app/deploy/start-render`가 `deploy/migrate_postgres.py`를 먼저 실행하며 실패 시 웹·계정 초기화를 시작하지 않습니다. 두 DB는 PostgreSQL 16이어야 하며 빈 대상만 수용합니다. 기존 대상이나 다른 원본의 완료 영수증은 거부합니다.

원본 DB의 새 연결을 읽기 전용으로 바꾸고 같은 앱 계정의 기존 연결을 종료한 뒤 전체 테이블을 SHARE 잠금합니다. PostgreSQL 16 pg_dump/pg_restore로 소유자·ACL을 제외한 스키마, 함수, 트리거, 데이터, 시퀀스를 트랜잭션 복원합니다. 대상 public 스키마의 Neon 소유권을 유지합니다. 테이블별 기본키 정렬 COPY 바이너리 SHA-256/건수와 시퀀스·트리거·함수·제약을 대조합니다. CHECK 식은 pg_dump의 동등한 배열 캐스트 재표현을 PostgreSQL 계획으로 정규화해 비교합니다.

완료 영수증을 대상의 `studio_migration.receipt`에 보존합니다. 재기동 시 같은 원본의 완료 영수증이 있으면 재복사하지 않아 전환 이후 쓰기를 보존합니다. 검증 전 오류는 원본의 읽기 전용 기본값을 원래대로 복원합니다. 복원이 끝났으나 대조 실패한 대상은 자동 삭제하지 않으며, 검토 후 별도 빈 대상으로 재시도합니다.

검증 완료 후에는 Render `DATABASE_URL`을 Neon 직접 연결로 변경하고 이전 전용 변수는 비웁니다. 시작 시 migrate를 실행하므로 직접 연결을 사용하며, 추후 별도 migration URL을 도입하면 앱 트래픽에 풀러를 적용할 수 있습니다. Blueprint의 원본 `fromDatabase`는 `sync: false`로 바꿔 재동기화 시 원본 연결로 돌아가지 않게 합니다. DB 정의는 보존합니다.

원본은 이후 쓰기 없이 보관합니다. 전환 후 되돌리려면 먼저 Neon 쓰기를 멈추고 새 데이터·이력을 대사/역이전한 후 원본에서 `ALTER DATABASE <원본> RESET default_transaction_read_only`를 실행하고 연결을 전환해야 합니다. 단순히 예전 주소로 돌아가면 전환 후 데이터가 누락됩니다. 원본 만료 전에 별도 보존 백업을 확보해야 합니다.

로컬 전용 `deploy/check_migration.py`는 일회용 DB에서 비관리자 소유권, 기존 대상 거부, 실패 시 원본 복구, 전체 대조, 대상 쓰기 및 재실행 시 보존을 검증합니다. 운영에 실행하지 않습니다. `check_hosted_access`는 실제 서비스 DB에서 다섯 역할의 비밀번호·CSRF·인증 API·정적 파일 요청 경로를 검증하며 비밀번호를 출력하거나 초기화하지 않습니다. 이는 Django 내부 HTTPS 요청 경로 검증이며 외부 인터넷 브라우저 검증과 구분합니다.

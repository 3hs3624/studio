교육자료 본문과 사용자가 첨부한 고해상도 엔티티 개선 이미지를 검토했다. 연결된 동영상과 본문에서 생략된 이미지의 내부 내용은 검토 완료로 간주하지 않는다.

## 1단계: 공통 UI와 데이터 계약

구현:
- 공통 작업 버튼 높이 36px, 모바일 40px, 버튼 내 간격 통일.
- 파란 그룹 추가 작업과 밝은 그룹 선택 목록 구분, 선택 상태 표시.
- 그룹/필드 속성 영역 분리, 아이콘과 이름을 함께 표시하는 타입 팔레트.
- 화면/워크플로우 18개 타입: 문자, 장문, 정수, 실수, DECIMAL, 논리, 날짜, 일시, 시간, 연월, 연도, JSON, JSON 목록, 사용자, UUID, 이메일, 전화, URL.
- 엔티티는 위 타입 및 선택/공통코드/엔티티 참조를 지원. 관계 선택의 조직·권한 검사는 기존 서비스에서 유지.
- 길이, DECIMAL precision/scale, 설명, 리터럴/허용된 자동 기본값 지원.
- DECIMAL은 문자열로 전달·저장하고 비교 시 Decimal 사용. 실수 변환 금지.
- JSON 크기·깊이·유한 수치 검증, 일시의 시간대 필수 검증.
- 기본값은 신규 생성 시에만 적용. 부분 수정/태스크 처리에서 기존 값을 덮어쓰지 않음.
- 저장된 초안과 게시본의 필드 변경 비교, 게시된 참조와 진행 건 수 표시.
- 기존 layout 없는 화면, 그룹 통제, 기존 게시 버전과 진행 건을 유지.

검증 결과는 실행 결과와 함께 최종 보고한다. 브라우저 미리보기는 합성 화면이며 운영 사이트 배포 검증을 대신하지 않는다.

## 이후 단계 — 아직 구현 완료가 아닌 항목

### 2. 저장 스키마 및 키·인덱스
- 실제 DB 타입 매핑 카탈로그, DBMS/버전별 길이·precision/scale 허용 규칙.
- 물리 스키마 변경 계획·사전 검사·적용 이력과 별도 권한의 스키마 작업자.
- 기존 JSON 데이터와 참조 보존, 중복 키·길이 초과·변환 실패 보고, 데이터 이관.
- 복합 PK·조회 API, 일반/UNIQUE 복합 인덱스 생성·삭제와 컬럼 순서.
- PostgreSQL 실적용 검증, 다른 DB는 실제 연결 검증 범위를 명확히 표시.
- 필드 수가 많은 엔티티의 검색·분할 표시·참조 지연 조회.

### 3. 화면 구성 및 업무 연결 확장
- Group → Set → Field 및 배치 영역 편집/실행 렌더링.
- 코드·참조·파일·사용자 정의 컴포넌트의 화면 디자이너 설정과 서버 계약.
- 비밀번호 입력은 해시 저장·조회 차단까지, 파일 입력은 실제 권한 있는 첨부 저장까지 구현해야 제공으로 간주.
- 엔티티/화면/워크플로우/규칙/API 간 명시적인 버전 연결 및 게시 전 참조 검증.
- 모든 참조에 대한 필드 삭제·유형 변경 영향도. 현재 보고는 게시 화면/엔티티 참조에 한정됨.

### 4. 플랫폼 구성 기능
- 일반·관계·통계·선택 팝업·트리 목록 디자이너.
- 자동 할당 규칙 우선순위 및 적용 사유.
- 규칙·후속 작업·알림·API 실행 순서와 실패/재시도 처리.
- 설정 게시 후 캐시 갱신 및 업무 생성 마법사.
- SQL 관리자 파라미터·제한·감사·미리보기 롤백.
- JSON 스키마 에디터, 대용량 본문 스트리밍, Boolean 저장 표현 변환.

### 5. 통합 검증·배포·산출물
- SR 등록→부서 승인→접수/배정→조치→사용자 확인→종료, 결재와 SLA/KPI 결과 회귀 검증.
- 사용자/부서/그룹/역할의 화면·행·필드·API 접근 검증.
- 기존 설치·단일 컨테이너·노트북 AP/DB Docker의 마이그레이션/스키마 작업자 검증.
- 검증된 커밋만 main에 반영 후 배포·접속 확인. 환경·계정·DB 보존.
- 최종 기능/화면/테이블/코드 정의서 갱신 및 요청된 Drive 경로에 작성.

전체 기능을 완료 또는 배포했다고 보고하려면 위 후속 단계를 구현·검증해야 한다.
